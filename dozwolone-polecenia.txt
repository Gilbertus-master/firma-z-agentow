# Lista dozwolonych poleceń i narzędzi – hook uprawnień blokuje DOMYŚLNIE wszystko, czego tu nie ma.
#
# Jak to działa (.claude/hooks/uprawnienia.py):
#   - polecenie Bash jest rozbierane na człony (;  &&  ||  |  $(…)  `…`  podpowłoki, bash -c '…', find -exec, xargs)
#     i KAŻDY człon musi zaczynać się od wpisu z sekcji [polecenia];
#   - wpis to nazwa polecenia albo nazwa z podpoleceniem („gh pr view” wpuszcza gh pr view, ale nie gh pr merge);
#   - czynności z uprawnienia.yaml (scalenie PR-a, wdrożenie, wysyłka, zapis przez HTTP…) mają własne poziomy
#     i idą swoją ścieżką – wpis tutaj ich nie odblokowuje;
#   - zakazy bezwzględne z zasady.md (git reset --hard, sudo, eval…) działają niezależnie od tej listy;
#   - polecenie spoza listy = czynność „spoza_listy” (poziom: właściciel) – przechodzi tylko z zaakceptowaną decyzją
#     (DECYZJA=D-RRRRMMDD-NN <polecenie>) albo po dopisaniu tutaj.
#
# Zmiana tej listy to „zmiana_zasad_lub_uprawnien”: tylko właściciel, przez PR. Agent nie dopisuje sobie poleceń sam.
# To jest barierka, nie piaskownica: interpreter z listy (python3, node, bash skrypt.sh) wykona dowolny kod,
# który dostanie. Im krótsza lista, tym mocniejsza barierka – usuń, czego Twoja organizacja nie używa.
